 - user 객체 전체를 얕게 복사하여 user2를 만들고, user2의 urls 프로퍼티에 원본 user.urls 객체를 다시 copyObject 함수로 복사하여 할당

 - 원본 객체와 동일한 구조를 가지면서 내부의 모든 값이 복사된, 참조를 공유하지 않는 완전히 독립적인 새로운 객체를 생성할 수 있음

### EX 1-17

### EX 2-1

### EX 2-2
 - 함수 내에서 매개변수와 이름이 같은 변수를 var로 선언할 때 호이스팅 규칙의 적용
 - 함수가 호출되면, 매개변수 x는 전달된 인자 1로 먼저 초기화되며, 같은 이름의 var x 선언은 이미 존재하는 매개변수 x에 영향을 주지 않음
 - 이후 var x = 2 라인에서 할당문이 실행되어 x의 값이 2로 변경되고, 마지막 console.log(x)는 2를 출력
 - 매개변수가 변수 선언보다 호이스팅 및 초기화에서 우선순위를 가짐을 알 수 있음

 - 함수 실행 컨텍스트를 준비할 때 매개변수를 어떻게 처리하는지 보여주는 코드
 - 코드의 실행 결과는 예제 2-2와 완전히 동일
 - 함수 호출 시 매개변수는 함수 내부의 일반 var 선언보다 먼저 처리되어 전달된 값으로 초기화

### EX 2-4

 - 코드의 실행 결과는 예제 2-2, 2-3과 동일

### EX 2-5
 - 이 예제는 함수 내에서 같은 이름의 변수 선언과 함수 선언이 함께 있을 때 호이스팅의 동작
 - 함수 선언문은 변수 선언과 달리, 선언과 동시에 함수 자체를 값으로 할당하는 과정까지 포함하여 최상단으로 끌어올려짐

### EX 2-6 & 2-7
 - 예제 2-5의 동작 방식을 설명하기 위해 호이스팅 과정을 거친 후의 상태를 개념적으로 나타낸 형태
 - 함수 선언문은 통째로 호이스팅되지만, 함수 표현식은 변수 선언 규칙에 따라 선언부만 호이스팅되어 실행 전 접근 시 동작이 다름

### EX 2-8
 - 함수를 정의하는 세 가지 방식인 함수 선언문, 익명 함수 표현식, 기명 함수 표현식
 - 함수 선언문은 함수명이 변수명이 됨
 - 익명 함수 표현식은 이름 없는 함수를 변수에 할당, 변수명이 함수명이 됨
 - 기명 함수 표현식은 변수명과 함수명을 다르게 설정할 수 있고, 함수명은 외부에서 직접 호출할 수 없음

### EX 2-9
 - 함수 선언문과 함수 표현식의 호이스팅 차이
 - 함수 선언문으로 정의되면 함수 전체가 호이스팅되므로, 코드 상단에서 정의부보다 먼저 호출해도 정상적으로 실행
 - 함수 표현식으로 정의되면 변수의 선언부만 호이스팅되고 함수 자체의 할당은 나중에 이루어지므로, 할당 이전에 호출하면 에러가 발생

### EX 2-11

 - 함수 선언문은 호이스팅될 때 코드 상 가장 마지막에 정의된 것이 이전 정의들을 덮어쓰기 때문에, 개발자의 의도와 다른 함수가 호출될 수 있음

### EX 2-12

 - 함수 표현식은 변수 선언만 호이스팅되므로, 함수가 실제로 할당되기 전에 호출하면 즉시 TypeError가 발생하여 문제를 조기에 발견할 수 있음
 - 함수 표현식은 함수의 사용 가능 시점을 명확히 하고 호이스팅으로 인한 혼란을 줄여주어 잠재적인 버그를 예방하는 데 더 안전한 방식으로 간주될 수 있음

 - 함수를 객체의 메서드로서 호출하면, 함수 내부의 this는 그 메서드를 소유한 객체를 가리킴

 - 메서드 호출 시 this는 항상 메서드(함수) 이름 바로 앞의 객체를 가리킴, 그 메서드를 호출한 주체가 this가 됨

### EX 3-9
 - 메서드 내부함수에서의 this
 - outer 메서드가 호출될 때 그 안의 this는 obj1을 가리키지만, 그 안의 innerFunc가 일반 함수로서 호출될 때 innerFunc 내부의 this는 전역 객체(window/global)를 가리킴
 - 내부 함수는 자신을 감싸는 외부 함수의 this를 자동으로 상속받지 않음
 - 동일한 innerFunc를 obj2의 메서드로 할당하고 메서드로서 호출하면, 그때 innerFunc 내부의 this는 호출 주체인 obj2를 가리킴

### EX 3-11

 - 화살표 함수는 일반 함수와 달리 자신만의 this를 바인딩하지 않고, 대신 함수가 정의될 때의 상위 스코프의 this를 그대로 물려받아 사용

### EX 3-12

### EX 3-13

### EX 3-17
 - call/apply 메서드의 활용: 유사배열객체에 배열 메서드를 적용
 - 유사 배열 객체는 실제 배열이 아니므로 직접 .push() 등을 호출할 수 없지만, call 또는 apply를 사용하면 obj에 배열 메서드를 실행할 수 있음

### EX 3-18
 - call/apply 메서드의 활용: arguments, NodeList에 배열 메서드를 적용

### EX 3-19
 - call/apply 메서드의 활용: 문자열에 배열 메서드 적용
 - 문자열도 length와 숫자 인덱스를 가진 유사 배열 객체의 특징을 가지므로, call 또는 apply를 통해 배열 메서드 일부를 사용 가능
 - every, some, map, reduce 등 원본 문자열을 변경하지 않는 배열 메서드들은 문자열에 적용하여 각 문자를 요소처럼 다룰 수 있음
 - push와 같이 원본을 변경해야 하는 메서드는 문자열의 불변성과 읽기 전용 length 속성 때문에 에러가 발생하거나 의도대로 동작하지 않음
